# AlphaPoint Sports dashboards

Public site: https://dylankelly0233-hoops.github.io/alphapoint-dashboards/ (cfb.html, nfl.html, cbb.html, nba.html, nhl.html, epl.html, mlb.html, golf.html)
Repo: github.com/dylankelly0233-hoops/alphapoint-dashboards (public). This folder is the local clone.

## How it runs
- **GitHub Actions** (`.github/workflows/build.yml`) runs `build_site.py` on a cron that asks for hourly runs but in practice runs about 3-4 times a day (GitHub's free scheduler is best-effort; an outside timer calling `workflow_dispatch` would make it hourly), on every push to code or data files, and on demand (`gh workflow run build.yml`). It builds the eight dashboards, commits `line_history_*.csv`, `ratings_history_*.csv` and the calibration logs (`projections_*.csv`, `source_history_*.csv`) back to the repo, and deploys `site/` to Pages.
- **Calibration logs** (internal, never shown on the site): `projections_{sport}.csv` keeps one row per game with our line and the market line when first and last seen before kickoff, the opener, confidence, guard flags and each source's own line. `source_history_{sport}.csv` keeps each source's rescaled rating per team per day. They feed the weekly tuning of source weights and home field; they are not a picks record. `weekly_review.py` scores them against final results (cached in git-ignored `results_*.csv`) and writes `last_review.md`; a Sunday 10:30 AM scheduled task follows `refresh_weekly_review.md`, runs it with `--calibrate` so `calibrate.py` re-tunes each sport's home edge and source weights (with shrinkage, step caps and bounds; changes logged in `calibration_log.csv`), pushes `calibration.json`, and emails Dylan the review. Dashboards read the tuned values through `extras.calibrated()`; the constants in each dashboard are the defaults. Don't edit `calibration.json` by hand. Since 2026-11-11 each sport's home edge and rating spread (`hfa`, `scale`) are fitted weekly to the market's own lines (`calibrate.tune_to_market`; `python calibrate.py --market-now` runs it immediately), because the market line is a far less noisy target than results; source weights stay results-based. The tuning also reads the rating spread (`scale`, via `extras.calibrated_value`), the NHL overtime adjustment (`tie_boost`) and the EPL draw adjustment (`dc_rho`). **Model performance** (`model_performance.py`, rendered by `perf_page.py` as a home-page tab, rebuilt on every build into git-ignored `performance.json`): accuracy vs. the closing line with standard errors, disagreement buckets, line movement toward our number, confidence levels, and research flags (value signals, tags, matchup edges; logged in the projections' `context` column from 2026-11-08). Not a picks record. `backtests.py` replays past seasons for NFL, CFB, CBB, NBA, NHL and EPL with a results-only walk-forward rating vs. historical closing lines and writes `backtests.json` (committed; rerun monthly, slow the first time: NBA / NHL closing lines come one game at a time from ESPN, cached in git-ignored `bt_*.csv`); its "realism" number (share of our disagreement with the close that shows up in results) is shown on the tab. The tab also scores each rating source alone from the logs. The same module prints the daily health check used in the 11 AM email (`refresh_cbb.md` step 2f).
- **Ratings are fetched by the build itself**, so the site needs nothing from the PC: CFB = Sagarin + SP+ (CFBD API), NFL = nfelo + Sagarin, CBB = TeamRankings predictive + our own `cbb_model.py` (ramps in from 3 games), with Torvik's committed preseason file fading out as it does; Warren Nolan was dropped 2026-11-02 for being far off the market (`cbb_ratings.py`). NBA = Sagarin + TeamRankings predictive + our own adjusted net rating from ESPN box scores (`nba_value_metrics.py`; its weight ramps up with games played). NHL = Sagarin + our expected-goals model (`nhl_model.py`: MoneyPuck team xG + goalie goals saved above expected), all in goals; games are projected as win probability / fair moneyline with ESPN's probable starting goalies, and the market is ESPN's no-vig moneyline. NHL lines are logged as goal margins so the shared logging and Sunday tuning work unchanged. EPL = our expected-goals model (`epl_model.py`: Poisson attack/defense fit to 70% xG + 30% goals from football-data.co.uk, Dixon-Coles scorelines) + ClubElo when its site is up; cards show home / draw / away vs. ESPN's no-vig three-way price, logged as goal margins. `epl_backtest.py` (model vs. closing odds: calibrated, but the market is sharper) and `epl_fatigue_backtest.py` (European midweek fatigue: no effect, z = −0.31, so `FATIGUE_TAG` stays False) are research scripts. Golf (`golf_model.py`, `golf_dashboard.py`) = PGA Tour + majors: skill from ESPN round scores (PGA Tour, DP World, LIV; field-strength adjusted, scores only, no strokes-gained categories), 20,000-run tournament simulation, compared with Kalshi winner / top 5 / 10 / 20 prices; `golf_backtest.py` is the walk-forward check; `golf_log_{season}.csv` (committed by the build) feeds the golf lines of the Sunday review, which Dylan uses to decide in Jan 2027 whether paid data is worth it. Golf is not in Best spots or the Sunday tuning. MLB (`mlb_model.py`, `mlb_dashboard.py`), phase 1 (offseason, live 2026-11-08): last season's final power ratings (TeamRankings + our BaseRuns run differential), value metrics (Pythagorean / BaseRuns wins, one-run and extra-inning records, Statcast hitting luck, bullpen ERA vs. FIP) and a starter ERA vs. FIP / xFIP / xERA table, from the MLB Stats API (individual non-commercial use) and Baseball Savant. Phase 2 before Opening Day 2027: game cards (moneyline, total, run line, probable-starter swing), backtest vs. ESPN closing odds, logging, Best spots. Until TeamRankings switches to the new season, CBB uses Warren Nolan + the committed Torvik preseason file `cbb_torvik_{season}.csv`. KenPom, Torvik and Sonny Moore block GitHub's servers; don't add them back as live sources.

## Code map
- `cfb_p4_dashboard.py`, `nfl_dashboard.py`, `cbb_dashboard.py`, `nba_dashboard.py`: one dashboard each (power ratings, value metrics, games, markets, injury wire).
- `*_value_metrics.py`: wins-over-expectation (W − xW) metrics for each sport.
- `dashboard_theme.py`: the shared look (page shell, CSS, logos, cards). `markets.py`: Kalshi win probability and spread liquidity. `injury_wire.py`: injury candidates and loading the curated file. `weather.py`: kickoff forecasts for outdoor football games (Open-Meteo; NFL stadium table, CFBD venues for CFB). `extras.py`: rating history and movers, the per-source "Sources" agreement row, the data-freshness strip, line movement, situational tags (CFB bounce-back, NFL teasers), team pop-up pages, and the `spots_*.json` feed behind the home page's best spots.
- Key settings sit near the top of each dashboard: `HFA_POINTS` (CFB 2.5, NFL 1.7, CBB 3.0, NBA 2.4), `SOURCE_WEIGHTS`, and the trade-signal thresholds in the value-metrics files.

## Working rules
- The site is a research tool, not a picks service. Dylan removed the pick-tracking scorecard on 2026-10-29; don't add pick logging, records or "bets to tail" features back.
- Secrets: the CFBD key lives in the `CFBD_API_KEY` Actions secret and in the git-ignored `cfbd_api_key.txt`. Never put it in code or commit it.
- Before pushing: `git pull --rebase`. The Actions bot commits line- and rating-history updates often.
- Don't commit local copies of `line_history_*.csv`, `ratings_history_*.csv`, `projections_*.csv` or `source_history_*.csv`. GitHub's builds own them; use `git checkout --` to discard local changes.
- Python: the NFL scripts need pyarrow (`C:\Users\dylan\PyCharmMiscProject\.venv\Scripts\python.exe` has it); the others run on the global `python`.
- GitHub CLI: `C:\Program Files\GitHub CLI\gh.exe`, logged in as dylankelly0233-hoops.
- To test a change locally, run the dashboard script with `CFB_NO_BROWSER` / `NFL_NO_BROWSER` / `CBB_NO_BROWSER` / `NBA_NO_BROWSER` set. Pushing the change triggers a live rebuild.
